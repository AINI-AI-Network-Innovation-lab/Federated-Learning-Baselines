# FedADMM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a practical FedADMM baseline to this Flower codebase, starting with the `g = 0` variant that fits the existing supervised learning pipeline.

**Architecture:** Keep the server strategy Flower-compatible and mostly FedAvg-shaped, while moving FedADMM-specific behavior into client-side training plus per-client persisted dual state. Use the existing registry/config/app structure so `algorithm="fedadmm"` works through the same entrypoints as other baselines.

**Tech Stack:** Python 3.11+, PyTorch, Flower, `unittest`/`pytest`, existing `fl_baselines` registry and client wrappers.

## Global Constraints

- Support `algorithm="fedadmm"` through the existing Flower server/client apps.
- Persist one FedADMM dual state per `client_id` under `output-dir`.
- Reuse the current model and dataset abstractions unchanged.
- Do not add a generic `g` proximal oracle in the first pass.
- Describe the result as a practical FedADMM adaptation for this repo, not a complete solver for arbitrary constrained composite optimization.
